# 專案背景與定位

日期：2026-08-08
來源：整合自 `~/practices/app2/docs/` 的 02（題目盤點）、03（題目評選）、06（競品修正）、11（總結）各篇中與本題相關的內容。

## 一、題目由來

本題出自台灣開放資料產品題目盤點（2026-08-07），從數千個 dataset 中以三個標準篩選：

1. **高利害關係**：查錯的代價大，使用者有強動機查。托育正是典型——家長焦慮感是全台灣最強的付費動機之一（參考月子中心、私幼的價格彈性）。
2. **原始資料難讀**：散落多來源、格式亂、需要清理與歸戶——加工本身就是價值與門檻。
3. **有 B 端願意付錢**：C 端在台灣很難收費，B2B 資料授權／API 才是可持續的變現。

本題入選五大候選題目（題目 5：托嬰中心／幼兒園裁罰紀錄＋異動推播），原始構想：

- 裁罰紀錄歸戶＋異動推播（「你追蹤的托嬰中心被裁罰了」）就是完整產品。
- B 端延伸：企業托育福利平台、保母媒合平台需要這個資料當信任層。

## 二、原始評估與兩項被推翻的假設

原始評估（2026-08-07）給了兩個後來被競品查核推翻的判斷：

1. ~~「仿製門檻在資料工程：22 縣市各自的網站、格式、更新頻率都不同，爬蟲維護是苦工。」~~
   實況：托嬰中心有社家署「社福機構資訊網」全國集中源，幼兒園有「全國教保資訊網」全國集中源——單一來源、一支爬蟲即可取得，仿製門檻遠低於原估。縣市分散、需逐一爬取的只剩補習班與課照中心。
2. ~~「機構頁吃 SEO」的獲客假設。~~
   實況：至少五個免費地圖加一個免費 app 已卡位查詢與 SEO 流量（詳見 `02_競品全景.md`），C 端查詢功能收不到錢，連「做得更好的查詢」都沒有空間。

## 三、查核後的最終定位

在五題的最終排序中，本題列為第五（最低優先），判定為「**資料層或不做**」：

1. **C 端故事基本出局**，剩下的合理形態是「資料層供應商」：
   - **持續備份**：對抗官方裁罰公告到期下架（本題真正的護城河，詳見 `03_資料源與護城河.md`）。
   - **負責人歸戶**：換牌重開偵測，目前沒人做，且最接近建商履歷題目的歸戶技術。
   - **B 端 API**：賣給托育媒合平台當信任層。
2. **裁罰異動推播訂閱**是唯一還空著的 C 端功能（沒有任何一家做追蹤通知），可當 API 的展示櫥窗，但不足以獨立撐起產品。
3. **補習班＋課照中心**仍是縣市分散、無人整合，是資料層的增量價值所在。
4. **與公益專案的關係**：資料層引用相同官方來源，各做各的；不搶查詢流量，甚至可考慮互相連結。

**C 端收費的最終判斷（2026-08-09 覆核）**：維持「不向 C 端收費」。第六階段免費地圖上線後 C 端內容明顯變厚（收費明細、多年度評鑑），但那強化的是導流與分享價值，不是付費意願——需求窗口短、免費替代品既成、付費牆與 SEO 驗收直接衝突。完整推論、零成本的意願測試方法，以及**「不向園所收費」這條紅線**，見 `05_行動計畫.md` 第五節。

## 四、一個反直覺的正面訊號

Bananny 托育小幫手證明台灣家長願意在托育領域付費（聯絡一次 490 元、年訂閱月付 99 元），但付的是「媒合」不是「查詢」。這反過來支持 B 端路線——Bananny、育兒神隊友這類平台正是「裁罰資料 API＋歸戶服務」的潛在買家；賣鏟子給淘金者，比自己下場淘金合理。

## 五、為什麼叫「幼兒園履歷」

命名對齊同一輪評估的第一名題目「建商履歷」：把散落的立案、評鑑、收費、裁罰、負責人異動歸戶到「一間機構」這個實體，形成一份可追溯的完整履歷。兩題共用同一套歸戶方法論——本題的負責人歸戶（換牌重開偵測）是建商履歷「一案建商偵測」的同型技術，規模較小，適合當練兵場。
