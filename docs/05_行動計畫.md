# 行動計畫

日期：2026-08-08
來源：整合自 `~/practices/app2/docs/` 的 06（修正後定位）、11（行動計畫）。

## 一、動工前的前置驗證（商業開發，非工程）

「資料層供應商」形態的市場規模是否值得做，取決於有幾家平台願意付錢——這是商業開發問題而非工程問題。

- **訪談 2–3 家潛在買家**：Bananny 托育小幫手、育兒神隊友 KidsMap 這類媒合／查詢平台，確認「裁罰資料 API＋負責人歸戶」的付費意願與價格帶。
- 訪談結果決定本專案是「做」還是「不做」——若無人願付，C 端推播訂閱不足以獨立撐起產品。

## 二、不必等待的行動：立即開始備份

無論前置驗證結果如何，**裁罰公告備份應立即開始**：

- 官方裁罰公告到期即下架（3 個月至 6 年不等），歷史資料是時間累積型資產，後進者無法回溯補抓。
- 越晚開始差距越大；備份成本近乎 0（兩支爬蟲、資料量數萬筆等級）。
- 這一步不依賴任何商業判斷，且是所有後續形態（推播、歸戶、API）的共同地基。

具體工作：

1. 寫全國教保資訊網（幼兒園）裁罰公告爬蟲，排程定期抓取並保存快照。
2. 寫社家署社福機構資訊網（托嬰中心）裁罰公告爬蟲，同上。
3. 建立異動偵測（diff）：新增裁罰、內容變更、公告下架都留紀錄。

## 三、若前置驗證通過：MVP 範圍

1. 托嬰＋幼兒園兩支爬蟲＋備份（已在第二步完成）。
2. 異動推播：LINE 官方帳號訂閱「追蹤機構」，被裁罰即通知。以推播訂閱數驗證留存，不做查詢入口（不與免費地圖搶流量）。
3. 負責人歸戶原型：機構—負責人實體對應，偵測換牌重開案例。
4. B 端 API 雛形：以歸戶後的資料當展示，回頭找訪談過的買家。

估計 0.5–1 人月、月費 NT$500–1,500 內（詳見 `04_成本評估.md`）。

## 四、持續觀察

- 免費競品是否開始做推播訂閱或負責人歸戶（若被做掉，僅剩空白全失，直接放棄）。
- 補習班／課照中心的縣市資料是否出現集中源（目前分散是增量價值所在）。
- 與建商履歷專案（同輪評估的第一名題目）的歸戶技術共用進度——本題的負責人歸戶可當其「一案建商偵測」的練兵場。

## 五、C 端收費評估（2026-08-09）

**結論：C 端不直接收費，維持免費並當成獲取通路與資料價值的展示場；營收回到 B 端。** 這是結構判斷，不是保守：

1. **需求窗口太短**。找園是一次性決策，密集期數週到數月，找到就結束。訂閱制要長期關係，這群人用完就走——註冊數會好看，續訂率不會。
2. **付費牆直接抵觸第六階段唯一的 KPI**。該階段定位就是 SEO 導流，驗收條件是機構頁被收錄；內容進付費牆要嘛不被索引，要嘛得做 `isAccessibleForFree` 那套並承擔 cloaking 風險（同一理由已否決登入牆，見 `06_工程執行計劃.md` 第六階段技術決策表）。
3. **免費替代品是既成事實**，且核心內容是政府公開資料，「為什麼要付錢看政府資料」很難回答——即使我們的整理品質明顯較高。

**若仍要驗證 C 端付費意願，先做零成本實驗、不要先蓋付費牆**：在機構頁放「完整履歷報告（含官方已下架的裁罰、同負責人的其他園所、同區收費與評鑑比較）」按鈕，點擊後只收 email 並顯示「整理中，完成後通知」。開發成本近乎為零，量到的是真實點擊率與留信率，比任何問卷準。點擊率低就結案，不必寫金流。

**真要收費時的形態**：一次性小額（單園報告）優於訂閱，才對得上短決策窗口；且付費買的必須是**彙整與比較**（跨園比較、關聯圖、下架時序），機構頁本身維持免費可索引。若做訂閱，賣的應是「入園後持續監看單一機構」的長期性（窗口三到四年），但那正是 LINE 推播免費就能做的事，屬留客手段而非收入來源。

**紅線：不向園所收取任何費用。** 不論包裝成認證、澄清說明權或優先顯示，只要園所付錢能影響自己裁罰紀錄的呈現方式，本站的正當性即不存在，且與勒索的距離比想像中近。這條在營收壓力下最容易被說服為「小小的例外」，故明列於此。

附帶觀察：`ncwis_centers.py` 與 `ece_schools.py` 上線後，我們有 1,906 家托嬰的收費明細與幼兒園的多年度評鑑歷史。價格與評鑑的日常查看頻率遠高於裁罰紀錄，是更好的分享誘因與 SEO 素材——這反而支持免費策略，拿來當鉤子的價值大於拿來收費。

## 六、明確不做的事

- 不做查詢入口與地圖（紅海，至少五個免費地圖已卡位）。
- 不與公益專案搶 SEO 流量；資料層各做各的，可考慮互相連結。
- 付費訂閱者達千人等級前不上 app（雙平台維護是一人團隊的負資產）。
