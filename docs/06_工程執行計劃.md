日期：2026-08-08
範圍：對應 `05_行動計畫.md` 第二節「立即開始備份」與第三節 MVP。本計劃只涵蓋工程面；商業驗證（買家訪談）另行進行，不阻塞第一、二階段。

## 一、目標與範圍

**現在就做（不等商業驗證）**

1. 幼兒園（全國教保資訊網）與托嬰中心（社家署）兩支裁罰公告爬蟲。
2. 原始快照備份：抓到什麼存什麼，對抗官方到期下架。
3. 異動偵測：新增裁罰、內容變更、公告下架都留下事件紀錄。

**驗證通過後才做**

4. LINE 推播訂閱（追蹤機構、被裁罰即通知）。
5. 負責人歸戶原型（換牌重開偵測）。
6. B 端 API 雛形。

**2026-08-09 計劃變更：加入免費地圖（行銷通路）**。原判斷「地圖是紅海、明確不做」（`05_行動計畫.md`）修正如下：行銷面需要一個可分享、可被搜尋的公開入口替 LINE 推播與 B 端展示導流。但定位不是「又一張查詢地圖」——與競品同質的查詢功能仍然不做——而是**差異化揭露**：下架狀態標示（官方已下架、本站保留）、公文 PDF 原檔（遮罩版）、處分時園名 vs 現園名的換牌線索、機構完整裁罰史。競品揭露深度查核與差異點依據見 `02_競品全景.md` 第六節（2026-08-09 補充查核）；個資揭露界線見本文件第十節。

**明確不做**：app；與免費競品同質的純查詢功能（做了也收不到錢，見 `02_競品全景.md`）。

## 二、資料源技術探勘結果（2026-08-08 實測）

### 幼兒園：全國教保資訊網

- 入口：`https://ap.ece.moe.edu.tw/webecems/punishSearch.aspx`
- 技術形態：ASP.NET WebForms。流程為先 GET 取得 `__VIEWSTATE`／`__EVENTVALIDATION`（需維持 session cookie），再以表單 POST 查詢。
- 查詢條件：`ddlKey`（`school_name` 園名模糊比對／`pobject` 負責人或行為人模糊比對）、`txtKeyNameS` 關鍵字、`ddlCityS` 縣市（空值＝全國）、`ddlAreaS` 鄉鎮市區。空關鍵字查全國可行。
- 結果列表：`GridView1` 卡片式列表，每頁約 10 筆（有裁罰紀錄的「園所」而非裁罰事件），欄位含園名、縣市、區、公私立、地址電話、核定人數、狀態。
- 翻頁：`__doPostBack('PageControl1$lbNextPage', '')`，需重送 VIEWSTATE。
- 裁罰詳情：每園的「檢視」按鈕實際是 `window.open('./dtl/punish_view.aspx?sch=<加密token>')`，token 可直接從列表頁 HTML 取出後 GET，**但 token 疑似綁定 session**——脫離原 session 請求時頁面主體為空。爬蟲需在同一 session 內完成「列表→詳情」。
- **注意**：站方 TLS 憑證鏈不完整（一般驗證會失敗，需自帶中繼憑證或關閉驗證）。這直接排除 Cloudflare Workers 當爬蟲執行環境（Workers 的 fetch 無法略過憑證驗證）。

### 托嬰中心：社家署

- 入口：托育媒合平臺 `https://ncwisweb.sfaa.gov.tw/home/penalty` 導向 `https://crc.sfaa.gov.tw/ChildYoungLaw/Sanction`（違反兒少法裁罰專區，涵蓋托嬰中心、托育人員與個人）。
- 技術形態：伺服器端渲染，查詢即 GET 參數：`?page=1&pagesize=10&name=&target=&city=0&startDate=&endDate=&dosearch=true`。首次請求會經 `AspxAutoDetectCookieSupport` 轉址，帶 cookie 重試即可。
- 列表欄位：編號、縣市、裁罰對象、違法條文、裁罰日期；每筆有詳情頁 `/ChildYoungLaw/Detail/{id}`（自然數 id，可直接遍歷或從列表收集）。實測 `pagesize=100` 有效，全量 20 頁、1,967 筆（2026-08-08）。
- 詳情頁含裁罰對象、依據、違法條文、事實摘要，並附正式公告 PDF（`/UploadFile/Sanction/*.pdf`），一併備份。
- 此站 CA 憑證缺 Subject Key Identifier，過不了 OpenSSL 3.x 嚴格驗證，爬蟲關閉 TLS 驗證（抓取公開資料，風險可接受）。
- `target` 分類值（2026-08-09 實測確認）：`all` 全部（197 頁）＝ `person` 行為人（179 頁）＋ `componey` 兒童及少年福利機構（19 頁，站方拼字如此）；另有 `match` 收出養媒合服務者（目前 0 筆）。現行爬蟲用空值 `target=` 等同 `all`，無漏抓。分類值可作為解析器區分機構／個人裁罰的輔助訊號（各分類分開掃列表即得每筆所屬分類）。
- city 代碼表（搜尋表單下拉）：0 全選、1 臺北市、2 基隆市、3 新北市、4 宜蘭縣、5 桃園市、6 新竹縣、7 苗栗縣、8 南投縣、9 彰化縣、10 雲林縣、11 嘉義縣、12 高雄市、13 屏東縣、14 花蓮縣、15 臺東縣、16 澎湖縣、17 金門縣、18 連江縣、19 臺中市、20 臺南市、21 新竹市、22 嘉義市。
- ncwisweb 中心頁（2026-08-09 實測確認）：各托嬰中心詳情頁 `/home/childcare-center/detail/{CW編號}` 有「違反法令紀錄」欄位（伺服器端渲染的 `<ul>` 清單），但抽查 22 家 crc 上有裁罰的立案中心（跨新北、新竹、臺南、高雄等）全數為空——欄位存在於模板、縣市實務不填。**結論：不補中心層裁罰爬蟲**。附帶發現：中心詳情頁的評鑑等級／年度、核定與實際收托數、準公共化資格、收退費等欄位對第四階段歸戶與機構履歷有價值，CW 編號穩定可作主鍵；查詢入口為 POST 表單（需 `_csrf` token 與 session cookie），屆時可另立中心主檔爬蟲。

### 共同觀察

- 兩站皆未見驗證碼與明顯反爬機制；資料量小（裁罰事件推估數千筆等級），低頻禮貌爬取即可。
- 引用時依政府資料開放授權條款標示來源（見 `03_資料源與護城河.md` 第五節）。

## 三、技術選型

| 項目 | 選擇 | 理由 |
|---|---|---|
| 爬蟲語言 | Python 3 標準函式庫（urllib＋http.cookiejar＋regex） | WebForms 的 session＋VIEWSTATE 流程用 cookiejar 即可處理；零依賴，本機與 Actions 都不用裝套件。兩站憑證皆有問題（教保網憑證鏈不完整、社家署 CA 缺 SKI），自建 ssl context 關閉驗證。不需要瀏覽器自動化（兩站皆非 SPA）。 |
| 執行環境與排程 | GitHub Actions scheduled workflow（cron） | 免費、零維運、log 可查；爬蟲屬低頻批次，不需常駐主機。 |
| 快照與資料儲存 | Git data repo（`preschool-resume-data`，private）：`raw/` 存原始 HTML＋公告 PDF、`data/` 存解析後 JSON。**穩定路徑、每日覆寫，git commit 歷史即時間軸**（kiang 模式），存檔前剝除 VIEWSTATE 等 session 雜訊避免無意義 diff | 資料量在 git 舒適區；**diff、歷史、下架回溯全部由 git 免費提供**，不必自建版本機制。相比每日快照目錄，repo 只隨實際變更成長。 |
| 異動偵測 | 解析後 JSON 以穩定主鍵比對前次狀態，產出事件 JSONL（append-only） | 事件流是後續推播的直接輸入；git commit 內容即人可讀的異動稽核紀錄。 |
| 推播（第三階段） | LINE Messaging API＋Cloudflare Workers/D1 | 承接 `04_成本評估.md` 的選型；推播服務不碰政府網站，無憑證問題。 |
| 免費地圖（第六階段） | 靜態站（Python SSG）＋Cloudflare Workers static assets＋NLSC WMTS 底圖 | 與第三階段共用 Cloudflare 帳號與部署管線；這階段不開 D1／KV／R2（無執行期狀態）。選型理由詳見第六節第六階段。 |
| LLM | 不用 | 裁罰事由原文呈現即可。 |

每月固定成本：第一、二階段 0 元（GitHub free tier 內）；第三階段起依 `04_成本評估.md` 上限 NT$500–1,500。

## 四、系統架構

```
GitHub Actions（cron 台北 05:30：平日增量 --new-only、週六全量）
  └─ crawler/sfaa_crc.py   托嬰：GET 列表逐頁 → 逐筆 Detail/{id}＋公告 PDF

old-mini systemd timer（每日 06:30，scripts/local_backup.sh＋scripts/systemd/）
  └─ crawler/ece_moe.py    幼兒園：session → 全國查詢 → 翻頁 → 逐園詳情
     （教保網封鎖境外 IP，GitHub Actions 連線逾時，只能從台灣 IP 抓；
       old-mini 為家中常開機的 Ubuntu Server，走 Tailscale 管理）
  │
  ▼
preschool-resume-data（git repo；穩定路徑，git 歷史即時間軸）
  ├─ raw/ece/list/pNNNN.html           查詢結果列表快照
  ├─ raw/ece/detail/{縣市}_{園名}.html  各園裁罰詳情
  ├─ raw/sfaa/list/pNNNN.html
  ├─ raw/sfaa/detail/{id}.html
  ├─ raw/sfaa/files/*.pdf              正式公告公文（不變動，抓一次）
  ├─ data/…/penalties.json             解析後現況（第二階段）
  └─ events/events.jsonl               異動事件 append-only（第二階段）
       │
       ▼（第三階段）
  Cloudflare Workers＋D1：訂閱管理、LINE 推播、（第五階段）B 端 API
```

增量／全量雙模式的原因：private repo 的 Actions 免費額度 2,000 分鐘/月，每日全量（約 4,000 筆詳情頁、禮貌延遲 2 秒）會超額。平日 `--new-only` 只抓新出現的詳情，週六全量補齊既有紀錄的內容變更。代價：既有機構的新裁罰最慢一週後入庫——第三階段做推播時再以「付費分鐘數或本機排程」換時效。

原則：**先備份、後解析**。解析失敗不影響快照落地；schema 日後可改，raw 永遠可重放（replay）。

## 五、資料模型（解析層）

```
penalty（裁罰事件）
  id            穩定主鍵。sfaa 用站方 Detail id；ece 無公開 id，
                用內容雜湊（機構名＋裁罰日期＋依據條文＋事由摘要）
  source        ece | sfaa
  institution   機構名稱（個人裁罰時為空，名字記在 person）
  person        負責人或行為人
  city / area   縣市／區
  law           依據法規條文
  fact          違規事由（原文）
  sanction      裁罰結果（原文）
  penalty_date  裁罰日期
  first_seen    首次抓到日
  last_seen     最後仍在線上日
  removed_at    偵測到下架日（null＝仍在線）

event（events.jsonl 每行一筆）
  type: new | changed | removed
  penalty_id、date、diff（changed 時記錄變更欄位）
```

`removed` 事件即護城河的計量單位：官方下架、我方仍有，就是累積的資產。
**護城河假設修正（2026-08-09）**：kiang 的檔案庫（幼兒園自 2014 年、兒少裁罰站 2,091 筆）以 MIT 授權公開於 GitHub，「後進者無法回溯補抓」不再成立——歷史縱深本身不是壁壘，**壁壘在解析品質（文號／生命週期／換牌線索）、事件流即時性與歸戶**。同時這是機會：見第六節 2.4 歷史回補。

機構主檔（institution）原訂留到第四階段歸戶時再建；**2026-08-09 調整：提前到第六階段 6.1 建立**（地圖需要機構維度與座標，且來源是 kiang 的兩份 MIT GeoJSON，不需自建爬蟲）。負責人實體（owner）仍留到第四階段，屆時從 penalty 與 6.2 產出的改名 alias 表回填。回補的歷史紀錄以 `origin` 欄位標示來源（`official`＝自抓快照／`kiang`＝回補），與官方可驗證的紀錄區隔。

### 第三階段：LINE 推播 MVP（週 4–6）

- LINE 官方帳號＋Messaging API webhook（Cloudflare Workers）。
- 訂閱模型：關鍵字追蹤機構 → 存 D1；Actions 產出新事件後呼叫推播 Worker。
- 驗收：外部使用者可完成「加好友 → 追蹤機構 → 收到裁罰通知」全流程。

### 第四階段：歸戶原型（週 6–8）

- 從 penalty 的 person 欄位建立負責人實體；同名＋跨機構＋時間序列規則比對，人工覆核介面可以先用表格檔案代替。
- 產出第一份「換牌重開」案例清單——這是給 B 端買家看的展示品。

### 第五階段：B 端 API 雛形（訪談後定規格）

- Workers＋D1 唯讀 API：機構履歷、裁罰歷史（含已下架）、負責人關聯。
- 規格由訪談過的買家需求決定，不預先過度設計。

### 第六階段：免費地圖（行銷通路；2026-08-09 新增，時點可與第三階段並行）

- 定位：LINE 推播與 B 端展示的公開導流入口，主打競品沒有的揭露深度（見第一節計劃變更），不與免費地圖比查詢功能。
- 形態：靜態站（penalties.json → 建站時產出頁面），零後端、零月費；機構頁固定網址吃長尾 SEO。
- 揭露內容依第十節分層原則：機構維度全揭露（含 `removed_at` 下架標示）。
- 每頁掛 LINE 官方帳號追蹤入口——地圖是通路，訂閱才是產品。

#### 前提查證（2026-08-09）

- **地理編碼不必自建**。現行 `penalties.json` 只到縣市／區層級，無地址與座標。kiang 另有兩份 MIT GeoJSON 可直接當機構主檔，各只需單一檔案，故不必比照 2.4 clone 整個 repo，改自 raw.githubusercontent.com 直取（同樣不觸及 kiang 自家伺服器）：
  - `kiang/ap.ece.moe.edu.tw` → `preschools.json`：7,664 家幼兒園，含座標、地址、負責人、公私立、核定人數、準公共年度、月費。
  - `kiang/ncwisweb.sfaa.gov.tw` → `docs/babycare.json`：2,045 家托嬰中心，含 CW 編號、座標、地址、電話、收托數、立案狀態。
  - 代價：機構主檔更新頻率受制於上游；停更時的退路是自建 ncwisweb 中心主檔爬蟲（第二節已探勘：POST 表單＋`_csrf`）＋TGOS 地理編碼。
- **底圖用 NLSC 國土測繪圖資服務雲 WMTS**（`https://wmts.nlsc.gov.tw/wmts/EMAP/...`）：免費、官方、中文地名齊全，標示出處即可。不用 Mapbox，也不自架 PMTiles／R2。

#### 技術決策（2026-08-09）

| 決策 | 選擇 | 理由 |
|---|---|---|
| 平台 | Cloudflare Workers static assets（不是 Pages） | 2026 年 Workers 對靜態資產已與 Pages 功能對等，官方對新專案導向 Workers；日後要加動態端點（B 端試用 API、LINE webhook 併站）不必搬家。與第三階段的 Workers＋D1 共用帳號與部署管線 |
| 渲染方式 | **SSG（建置時產生靜態頁），不走 SSR** | 內容一天只變一次（diff 08:30 跑完才有新資料），SSR 每次請求都在重算同一份輸出。三個決定性理由：<br>① **計費**：靜態資產請求免費且無上限、不計 Worker 呼叫；SSR 每次瀏覽即一次呼叫，免費方案 10 萬次／日，超額回 Error 1027＝整站掛掉。本站唯一目的是被爬，爬蟲反覆掃 9,709 頁正好是最容易爆額度的流量形態。<br>② **個資可驗收**：6.3 的完成定義「產物以正則掃不到自然人姓名」需要一個可 grep 的目錄；SSR 沒有產物，只能證明程式碼看起來沒漏，不能證明所有輸出都沒漏。這是第十節唯一能自動化把關的關卡，不換。<br>③ **失效模式**：資料管線壞掉時 SSG 續服舊資料；SSR 的 D1 schema 出錯即全站 500。本專案無 on-call。<br>SEO 上兩者對爬蟲都是 HTML，SSR 只是 TTFB 較差。重建成本也不是問題：產 1 萬頁數十秒，`wrangler deploy` 依內容雜湊只上傳變動檔 |
| 這階段**不開**的服務 | D1／KV／R2／Queues | 全站是建置時產生的靜態頁，無執行期狀態。多開一個服務只多一份維運面。R2 僅在 PDF 遮罩版上線或撞檔案數上限時才需要 |
| 建頁範圍 | 全部 9,709 家機構各一頁 | 長尾 SEO 最大化。裁罰**不另立頁**、內嵌於機構頁，以控制檔案數：9,709 機構＋22 縣市＋約 370 鄉鎮＋資產 ≈ 10,100 檔，免費方案上限 20,000 檔（單檔 25 MiB），餘裕約一半。無裁罰的機構頁靠基本資料／準公共／收費／核定人數／同負責人關聯撐內容量，避免被判薄頁面 |
| 個資 | MVP 自然人裁罰**整筆不進公開層**，負責人姓名只用於內部歸戶不外顯 | 第十節的公布期限分級尚待函詢；採最保守預設讓上線不被法遵前置阻塞，函詢結果回來後只是放寬 |
| 公告 PDF | MVP 不放原檔 | 985 份公文自動遮罩無法保證可靠，一次漏網即實現第十節要防的風險。改呈現解析後全文欄位，標註「原始公文本站存檔」 |
| 網域 | 先 `workers.dev`（6a），正式網域留到 6b | `workers.dev` 不像 `pages.dev` 預覽版會自動 noindex，因此 6a 期間**主動全站掛 `X-Robots-Tag: noindex`**，避免暫時網址被收錄、日後換域產生重複內容與 301 債。SEO 驗收整批延到 6b |

**SSR 的升級觸發條件**（滿足其一才重新評估，不預先做）：

1. **頁面組合爆炸**：第四階段歸戶若要做「負責人 × 機構 × 年度」交叉頁而撞上 20,000 檔上限。注意此時第一選項是升 Workers Paid（US$5／月，10 萬檔），比改架構便宜得多——真正逼出 SSR 的是六位數頁面。
2. **需要真的查詢**：前端在單一 GeoJSON 上過濾撐得住 9,709 筆；全文檢索或跨欄位條件組合撐不住。
3. **第五階段 B 端 API 上線**：公開站與 API 共用同一層 D1 查詢才有整合價值——但那也只需把 `/api/*` 交給 Worker，機構頁仍維持靜態。

三者都不需要搬家：Workers static assets 的預設路由是「命中靜態檔即直送、不叫 Worker」，未命中才落到 Worker，所以動態路由是後加的設定而非架構改寫。**陷阱**：`run_worker_first` 會強制所有請求進 Worker，且免費額度用盡時回 429 而不退回送靜態檔——非必要不開。

**公開／私有邊界**：資料 repo 是 private，本站是公開的。建置流程必須經過一層明確的「公開層欄位白名單」投影，不得直接發佈 `penalties.json`。

**6.2 的重要發現：托嬰側的公開內容幾乎是空的（2026-08-09，待決策）**

sfaa 2,024 筆裁罰的對象分布：**自然人 1,831 筆（90.5%）**、未立案或稽查時無招牌 75、站方歸為機構但實為人名 67、課後照顧班等非本站範圍 2，真正指向立案托嬰中心的只有 **49 筆**，其中 24 筆對上名冊（其餘 20 家已停辦、5 家換牌後接不到）。

也就是說，在「自然人裁罰整筆不進公開層」的 MVP 決策下，**2,045 家托嬰中心裡只有約 24 家會在地圖上顯示裁罰**。托嬰半邊實質是一張沒有內容的圖。三個選項，動 6.4 之前要決定：

1. **維持現狀**：托嬰中心只呈現主檔資訊（收托數、評鑑、收費），裁罰揭露以幼兒園為主。最保守，但托嬰家長來了看不到差異化內容。
2. **托嬰改採「機構去識別化」揭露**：自然人裁罰不指名，但仍以「本區○年有 N 件托育人員裁罰」的統計形式呈現。個資風險低（不可識別特定人），資訊價值仍在。
3. **重新評估姓名揭露**：把第十節的公布期限函詢提前，確認期限內姓名可照登——但這會讓上線被法遵前置卡住，與原決策相反。

幼兒園側沒有這個問題：ece 6,896 筆全部是機構維度，直接可用。

**6.1 的後續強化：托嬰中心主檔改自建（時點在 6.4，不阻塞前面工作）**

托嬰中心主檔目前取自 kiang 的 `babycare.json`，那是他抓 ncwisweb 詳情頁後的 8 欄投影。改成自己爬 ncwisweb 的取捨（2026-08-09 查證 `kiang/ncwisweb.sfaa.gov.tw/scripts/01_fetch.php`）：

- **ncwisweb 不提供經緯度**。kiang 是拿「所在地」（截到「號」）打 NLSC MapSearch（`api.nlsc.gov.tw/MapSearch/ContentSearch` → `QuerySearch`）geocode，快取在 `raw/address/`。所以自建不是換來源，是**接手地理編碼**。
- 失敗率非零：他的 `docs/data/` 有 2,346 家，`babycare.json` 只有 2,045 家——`02_detail2geojson.php` 以 `!empty(longitude)` 過濾，約 300 家（13%）geocode 不到被丟掉（含少量同 id 跨縣市重複）。自建須先決定這批怎麼處理（列表收錄但地圖不標／人工補）。
- NLSC 那支是 `maps.nlsc.gov.tw` 網頁背後的介面（靠 `Origin`／`Referer` header），非正式公開 API，無服務保證；正式管道是 TGOS 地理編碼服務（需申請）。等於把個人專案依賴換成未公開介面依賴，風險換位置而非消失。
- 只解決一半：幼兒園 7,664 家的主檔與座標仍來自 kiang 的 `preschools.json`。
- 待測：ncwisweb 是否封境外 IP（crc 可從 Actions 抓，但為不同主機）；TLS 同 sfaa 網域，沿用關閉驗證的 ssl context。

**動機（也是決定在 6.4 做的原因）**：ncwisweb 詳情頁的欄位遠比那 8 欄豐富——評鑑等級＋年度、準公共化資格、核定／實際收托、總／室內／室外面積、公共安全與消防核備文號、各類工作人員數、**收費情形明細**（托育費／註冊費／餐點費逐項）、退費說明、負責人姓名。這正是撐住「無裁罰機構頁不算薄頁面」與家長實際比較需求的內容。等 6.4 排版面時具體感受到缺料，再一併定爬蟲與欄位需求，會比現在憑空設計準；屆時 6.2 的對照結果也會指出哪些欄位真的有用。定位是「機構主檔爬蟲」，月更即可，不進每日排程。kiang 的 `raw/address/*.json`（2,701 筆 NLSC 結果，MIT）可當 geocode 快取種子。

## 七、排程與維運

- 頻率：每日 1 次；社家署走 GitHub Actions（台北 05:30）、教保網走 old-mini 的 systemd timer（06:30，`Persistent=true` 停機補跑）。平日增量、週六全量（見第四節）。
- 解析＋diff：old-mini 的 `preschool-diff.timer`（08:30，兩軌備份都完成後）單點執行 `scripts/local_diff.sh`，產出 `data/{source}/penalties.json` 與 `events/events.jsonl` 並 commit 至資料 repo。單點執行避免競態；diff 引擎解析失敗或 removed 異常量時不寫檔不 commit，異常留在 `~/preschool-diff.log`。
- old-mini 的 GitHub 存取：兩把 deploy key（程式 repo 唯讀、資料 repo 可寫），SSH host 別名 `github-code`／`github-data`。
- 禮貌性：單執行緒、請求間隔 2–3 秒、自訂 User-Agent 附聯絡方式。
- 監控（2026-08-09 上線）：三軌排程各自在資料 repo 寫心跳檔 `status/{job}.json`（台北日期＋exit code，每日必寫）；`watchdog.yml`（Actions，台北 09:30）檢查三個心跳「是今天的且 exit=0」，任一不符即讓 workflow 失敗，用 GitHub 原生失敗通知信告警——不依賴任何外部通知服務。涵蓋：爬蟲失敗、解析失敗、old-mini 離線或 timer 沒跑（心跳過期）。站方改版的靜默失敗由解析層攔截：涵蓋率不到 100% 時 diff 引擎 exit 1（觸發告警），removed 異常量另有警戒值擋住誤判下架。
- 站方改版時：raw 快照仍照抓（整頁存檔不受 schema 影響），解析器再跟上。

## 十、法遵：個資分層揭露原則（2026-08-09；工程決策用分析，非法律意見）

**著作權／授權面——取得與回補無障礙**：

- 著作權法第 9 條：公文（裁處書、公告）不得為著作權標的；裁罰紀錄屬事實資料，不受著作權保護。
- kiang 三個資料 repo（`preschools`、`ap.ece.moe.edu.tw`、`ncwisweb.sfaa.gov.tw`）皆為 MIT 授權，明示允許複製、修改、散布與商業利用，僅需保留授權聲明（2026-08-09 查核）。
- 官方資料依政府資料開放授權條款標示來源。

**個資法面——風險在利用方式，與資料來源無關**：

- 關鍵區分：**機構名稱是法人資料，不受個資法保護；負責人、行為人姓名是個資**。
- 蒐集處理的依據：個資法第 19 條第 1 項第 7 款「取自於一般可得之來源」＋公共利益。
- 風險核心＝但書「當事人顯有更值得保護之重大利益」：官方公告依處分輕重設 3 個月～6 年公布期限，到期下架是主管機關的利益衡量結果。**逾期後繼續以可搜尋姓名之方式公開自然人裁罰紀錄**，當事人可依第 11 條第 3 項請求刪除或停止利用。

**分層揭露設計（把法律線變成產品架構）**：

| 層 | 內容 | 個資風險 |
|---|---|---|
| 公開層（地圖） | 機構維度全揭露（含下架標示、換牌線索）；自然人姓名於官方公布期限內照登、**逾期遮罩**（王○○）；PDF 提供遮罩版 | 低（主體為法人資料） |
| 內部層（歸戶） | 完整姓名用於負責人歸戶運算，不對外 | 中，屬內部處理 |

遮罩期限的計算需要「各處分之公布期限」對照表（依處分輕重 3 個月～6 年），在第六階段動工前向主管機關函詢或由律師確認分級規則。
