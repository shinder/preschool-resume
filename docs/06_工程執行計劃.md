# 工程執行計劃

日期：2026-08-08
範圍：對應 `05_行動計畫.md` 第二節「立即開始備份」與第三節 MVP。本計劃只涵蓋工程面；商業驗證（買家訪談）另行進行，不阻塞第一、二階段。

## 一、目標與範圍

**現在就做（不等商業驗證）**

1. 幼兒園（全國教保資訊網）與托嬰中心（社家署）兩支裁罰公告爬蟲。
2. 原始快照備份：抓到什麼存什麼，對抗官方到期下架。
3. 異動偵測：新增裁罰、內容變更、公告下架都留下事件紀錄。

**驗證通過後才做**

4. LINE 推播訂閱（追蹤機構、被裁罰即通知）。
5. 負責人歸戶原型（換牌重開偵測）。
6. B 端 API 雛形。

**明確不做**：查詢入口、地圖、app（見 `05_行動計畫.md` 第五節）。

## 二、資料源技術探勘結果（2026-08-08 實測）

### 幼兒園：全國教保資訊網

- 入口：`https://ap.ece.moe.edu.tw/webecems/punishSearch.aspx`
- 技術形態：ASP.NET WebForms。流程為先 GET 取得 `__VIEWSTATE`／`__EVENTVALIDATION`（需維持 session cookie），再以表單 POST 查詢。
- 查詢條件：`ddlKey`（`school_name` 園名模糊比對／`pobject` 負責人或行為人模糊比對）、`txtKeyNameS` 關鍵字、`ddlCityS` 縣市（空值＝全國）、`ddlAreaS` 鄉鎮市區。空關鍵字查全國可行。
- 結果列表：`GridView1` 卡片式列表，每頁約 10 筆（有裁罰紀錄的「園所」而非裁罰事件），欄位含園名、縣市、區、公私立、地址電話、核定人數、狀態。
- 翻頁：`__doPostBack('PageControl1$lbNextPage', '')`，需重送 VIEWSTATE。
- 裁罰詳情：每園的「檢視」按鈕實際是 `window.open('./dtl/punish_view.aspx?sch=<加密token>')`，token 可直接從列表頁 HTML 取出後 GET，**但 token 疑似綁定 session**——脫離原 session 請求時頁面主體為空。爬蟲需在同一 session 內完成「列表→詳情」。
- **注意**：站方 TLS 憑證鏈不完整（一般驗證會失敗，需自帶中繼憑證或關閉驗證）。這直接排除 Cloudflare Workers 當爬蟲執行環境（Workers 的 fetch 無法略過憑證驗證）。

### 托嬰中心：社家署

- 入口：托育媒合平臺 `https://ncwisweb.sfaa.gov.tw/home/penalty` 導向 `https://crc.sfaa.gov.tw/ChildYoungLaw/Sanction`（違反兒少法裁罰專區，涵蓋托嬰中心、托育人員與個人）。
- 技術形態：伺服器端渲染，查詢即 GET 參數：`?page=1&pagesize=10&name=&target=&city=0&startDate=&endDate=&dosearch=true`。首次請求會經 `AspxAutoDetectCookieSupport` 轉址，帶 cookie 重試即可。
- 列表欄位：編號、縣市、裁罰對象、違法條文、裁罰日期；每筆有詳情頁 `/ChildYoungLaw/Detail/{id}`（自然數 id，可直接遍歷或從列表收集）。實測 `pagesize=100` 有效，全量 20 頁、1,967 筆（2026-08-08）。
- 詳情頁含裁罰對象、依據、違法條文、事實摘要，並附正式公告 PDF（`/UploadFile/Sanction/*.pdf`），一併備份。
- 此站 CA 憑證缺 Subject Key Identifier，過不了 OpenSSL 3.x 嚴格驗證，爬蟲關閉 TLS 驗證（抓取公開資料，風險可接受）。
- 待確認（第一階段內完成）：`target` 參數的分類值（機構／個人）；ncwisweb 各托嬰中心頁是否另有 crc 站沒有的裁罰欄位，若有則補一支中心層爬蟲。

### 共同觀察

- 兩站皆未見驗證碼與明顯反爬機制；資料量小（裁罰事件推估數千筆等級），低頻禮貌爬取即可。
- 引用時依政府資料開放授權條款標示來源（見 `03_資料源與護城河.md` 第五節）。

## 三、技術選型

| 項目 | 選擇 | 理由 |
|---|---|---|
| 爬蟲語言 | Python 3 標準函式庫（urllib＋http.cookiejar＋regex） | WebForms 的 session＋VIEWSTATE 流程用 cookiejar 即可處理；零依賴，本機與 Actions 都不用裝套件。兩站憑證皆有問題（教保網憑證鏈不完整、社家署 CA 缺 SKI），自建 ssl context 關閉驗證。不需要瀏覽器自動化（兩站皆非 SPA）。 |
| 執行環境與排程 | GitHub Actions scheduled workflow（cron） | 免費、零維運、log 可查；爬蟲屬低頻批次，不需常駐主機。 |
| 快照與資料儲存 | Git data repo（`preschool-resume-data`，private）：`raw/` 存原始 HTML＋公告 PDF、`data/` 存解析後 JSON。**穩定路徑、每日覆寫，git commit 歷史即時間軸**（kiang 模式），存檔前剝除 VIEWSTATE 等 session 雜訊避免無意義 diff | 資料量在 git 舒適區；**diff、歷史、下架回溯全部由 git 免費提供**，不必自建版本機制。相比每日快照目錄，repo 只隨實際變更成長。 |
| 異動偵測 | 解析後 JSON 以穩定主鍵比對前次狀態，產出事件 JSONL（append-only） | 事件流是後續推播的直接輸入；git commit 內容即人可讀的異動稽核紀錄。 |
| 推播（第三階段） | LINE Messaging API＋Cloudflare Workers/D1 | 承接 `04_成本評估.md` 的選型；推播服務不碰政府網站，無憑證問題。 |
| LLM | 不用 | 裁罰事由原文呈現即可。 |

每月固定成本：第一、二階段 0 元（GitHub free tier 內）；第三階段起依 `04_成本評估.md` 上限 NT$500–1,500。

## 四、系統架構

```
GitHub Actions（cron 台北 05:30：平日增量 --new-only、週六全量）
  └─ crawler/sfaa_crc.py   托嬰：GET 列表逐頁 → 逐筆 Detail/{id}＋公告 PDF

old-mini systemd timer（每日 06:30，scripts/local_backup.sh＋scripts/systemd/）
  └─ crawler/ece_moe.py    幼兒園：session → 全國查詢 → 翻頁 → 逐園詳情
     （教保網封鎖境外 IP，GitHub Actions 連線逾時，只能從台灣 IP 抓；
       old-mini 為家中常開機的 Ubuntu Server，走 Tailscale 管理）
  │
  ▼
preschool-resume-data（git repo；穩定路徑，git 歷史即時間軸）
  ├─ raw/ece/list/pNNNN.html           查詢結果列表快照
  ├─ raw/ece/detail/{縣市}_{園名}.html  各園裁罰詳情
  ├─ raw/sfaa/list/pNNNN.html
  ├─ raw/sfaa/detail/{id}.html
  ├─ raw/sfaa/files/*.pdf              正式公告公文（不變動，抓一次）
  ├─ data/…/penalties.json             解析後現況（第二階段）
  └─ events/events.jsonl               異動事件 append-only（第二階段）
       │
       ▼（第三階段）
  Cloudflare Workers＋D1：訂閱管理、LINE 推播、（第五階段）B 端 API
```

增量／全量雙模式的原因：private repo 的 Actions 免費額度 2,000 分鐘/月，每日全量（約 4,000 筆詳情頁、禮貌延遲 2 秒）會超額。平日 `--new-only` 只抓新出現的詳情，週六全量補齊既有紀錄的內容變更。代價：既有機構的新裁罰最慢一週後入庫——第三階段做推播時再以「付費分鐘數或本機排程」換時效。

原則：**先備份、後解析**。解析失敗不影響快照落地；schema 日後可改，raw 永遠可重放（replay）。

## 五、資料模型（解析層）

```
penalty（裁罰事件）
  id            穩定主鍵。sfaa 用站方 Detail id；ece 無公開 id，
                用內容雜湊（機構名＋裁罰日期＋依據條文＋事由摘要）
  source        ece | sfaa
  institution   機構名稱（個人裁罰時為空，名字記在 person）
  person        負責人或行為人
  city / area   縣市／區
  law           依據法規條文
  fact          違規事由（原文）
  sanction      裁罰結果（原文）
  penalty_date  裁罰日期
  first_seen    首次抓到日
  last_seen     最後仍在線上日
  removed_at    偵測到下架日（null＝仍在線）

event（events.jsonl 每行一筆）
  type: new | changed | removed
  penalty_id、date、diff（changed 時記錄變更欄位）
```

`removed` 事件即護城河的計量單位：官方下架、我方仍有，就是累積的資產。

機構主檔（institution）與負責人實體（owner）留到第四階段歸戶時再建，屆時從 penalty 累積資料回填。

### 第三階段：LINE 推播 MVP（週 4–6）

- LINE 官方帳號＋Messaging API webhook（Cloudflare Workers）。
- 訂閱模型：關鍵字追蹤機構 → 存 D1；Actions 產出新事件後呼叫推播 Worker。
- 驗收：外部使用者可完成「加好友 → 追蹤機構 → 收到裁罰通知」全流程。

### 第四階段：歸戶原型（週 6–8）

- 從 penalty 的 person 欄位建立負責人實體；同名＋跨機構＋時間序列規則比對，人工覆核介面可以先用表格檔案代替。
- 產出第一份「換牌重開」案例清單——這是給 B 端買家看的展示品。

### 第五階段：B 端 API 雛形（訪談後定規格）

- Workers＋D1 唯讀 API：機構履歷、裁罰歷史（含已下架）、負責人關聯。
- 規格由訪談過的買家需求決定，不預先過度設計。

## 七、排程與維運

- 頻率：每日 1 次；社家署走 GitHub Actions（台北 05:30）、教保網走 old-mini 的 systemd timer（06:30，`Persistent=true` 停機補跑）。平日增量、週六全量（見第四節）。
- old-mini 的 GitHub 存取：兩把 deploy key（程式 repo 唯讀、資料 repo 可寫），SSH host 別名 `github-code`／`github-data`。
- 禮貌性：單執行緒、請求間隔 2–3 秒、自訂 User-Agent 附聯絡方式。
- 監控：Actions 失敗通知；另加「連續 N 天抓到 0 筆新資料且頁面結構變動」的告警（防站改版造成靜默失敗）。
- 站方改版時：raw 快照仍照抓（整頁存檔不受 schema 影響），解析器再跟上。

## 八、風險與對策

| 風險 | 對策 |
|---|---|
| 教保網詳情 token 綁 session，行為日後改變 | 爬蟲以「同 session 完成列表＋詳情」為基本設計；若失效改走 postback 模擬 |
| 站方改版導致解析失敗 | 先備份後解析；解析涵蓋率告警；raw 可重放 |
| 站方封鎖或加驗證碼 | 低頻禮貌爬取降低機率；真發生時評估備援（改由住宅網路排程執行）。已發生一例：教保網封鎖境外 IP，改本機 launchd 排程解決 |
| old-mini 停機或家用網路斷線 | systemd `Persistent=true` 開機補跑；連續失敗靠每週人工抽查 log（`~/preschool-backup.log`）；長期不可用時改台灣 VPS |
| GitHub Actions cron 漂移或停跑 | 每日一次的用途可容忍漂移；停跑靠失敗通知＋每週人工抽查 |
| 公告 PDF 累積使資料 repo 過大（GitHub 建議 < 1GB） | 目前估約 200MB；超標時把 `raw/sfaa/files/` 移到 Cloudflare R2 或獨立 repo |
| 個資疑慮（裁罰對象為自然人） | 只引用政府已公開之裁罰公告並標示來源；下架資料的對外呈現政策在第五階段 API 設計時另議（備份本身不對外） |
